# 혼잡도 데이터 확인 결과 (Phase 0)

**결론: 부산 BIMS 공개 API에는 실시간 혼잡도(재차인원·혼잡 단계)가 없다.** (2026-10-21 확인)

## 근거
- 6개 기능 응답 필드 전수 확인 (`docs/api-notes/busan-bims.md`) — 혼잡도 관련 필드 없음
- 유일한 후보 `seat1/seat2`(잔여좌석 추정): 서면 일대 26개 정류장, 182개 노선-도착 행, 325개 값이 **모두 -1**
  - 일반·급행·마을·심야버스 모두 -1 → 사실상 제공되지 않음
  - 표본: `data/samples/stopArr_seomyeon_all.xml`
- 활용가이드 docx에서 `seat` 정의 확인은 아직 안 함 (확인되면 이 문서 갱신)

## 대체안 (사용자 결정 필요)

### A. 배차 간격 기반 혼잡 추정 — 권장
데이터만으로 바로 계산 가능.
- 앞차와의 간격이 평소 배차보다 크면, 그 버스는 그동안 쌓인 승객을 태워 붐빈다.
- 계산에 쓰는 값:
  - `min2 - min1` : 1번째·2번째 버스 간격
  - `busInfoByRouteId` 버스 위치 : 1번째 버스 앞차와의 간격
  - `busInfo.headwaypeak/headwaynorm` : 평소 배차 간격
- 간격 비율 = 실제 간격 / 평소 배차 → 0.7 미만 여유, ~1.3 보통, ~1.8 혼잡, 그 이상 매우혼잡 (초기값, 조정 필요)
- 덤: "앞차 바로 뒤에 붙어 오는 차(간격 짧음)"는 한산 → 3순위 "다음 차 타기" 판단에 그대로 쓸 수 있음

### B. 사용자 제보
탑승 후 여유/보통/혼잡 한 번 탭 → 노선·시간대·정류장별로 쌓아서 A의 추정을 보정. 개인용이라 본인 출퇴근 구간 데이터만 쌓여도 효과 있음.

### C. 혼잡도 기준 보류
최단 시간 + 다음 차 비교만으로 MVP.

### D. 과거 승하차 통계 기반 "평소 혼잡도"
- 출처: 공공데이터포털 [부산광역시_버스노선별 승하차 정보](https://www.data.go.kr/data/15123610/fileData.do) (파일 `data/raw/busan_boarding_20230731.csv`, CP949)
- 내용: 노선별·정류장순서별 **30분 단위 승차·하차 건수** (교통카드 기준), 161개 노선, 17,088행
- 하루치(2023-07-31, 월요일) 1회성 데이터. 승차 합계 약 104만 건 → 부산 시내버스 하루 이용량 규모
- 계산: 노선 정류장 순서대로 (승차 - 하차) 누적 → **노선·정류장·시간대별 평소 재차인원**
- 한계
  - 하차 태그가 승차의 43%만 기록됨 → 하차를 보정(승차 합계에 맞춰 비례 확대)해야 함
  - 2023년 하루치 → 이후 노선 개편 반영 안 됨, 요일·계절 차이 없음
  - `정류장코드`(7자리)가 BIMS `bstopid`(9자리)·`arsno`(5자리)와 다름 → 노선번호+정류장순서+정류장명으로 매칭 필요
- 예: 83번 오전 8시대, 서면 도착 시점 누적 약 130명(보정 전) → 노선 간 상대 비교용으로 사용
- 최신 데이터는 부산시 대중교통과에 **공공데이터 제공신청**으로 요청 가능 (이 파일도 제공신청으로 공개된 것)

### E. 날씨 보정 (선택)
기상청 단기예보 API로 비·폭염 시 혼잡 단계 한 단계 상향. 효과 대비 우선순위 낮음.

## 권장
**D(평소 혼잡도) × A(지금 배차 간격 보정)로 시작 + B(제보)를 나중에 추가.**
- D가 "이 노선은 이 시간 이 정류장에서 원래 붐비는가"를,
- A가 "지금 오는 이 버스는 평소보다 더 붐비는가/덜 붐비는가"를 맡는다.
- 화면에는 "추정 혼잡도"로 표시해 실측이 아님을 밝힌다.
